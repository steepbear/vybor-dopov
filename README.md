# Выбор допов — демонстрационный сервис V4

Статическое веб-приложение для учеников и методологов. Создано на HTML, CSS и JavaScript и может размещаться на GitHub Pages. **Это демонстрация с вымышленными учениками, не рабочая система регистрации персональных данных.**

## Публикация на GitHub Pages

1. Распаковать архив. В корень отдельного репозитория загрузить **`index.html`, `style.css`, `app.js`, `data.js`**. Файлы `README.md` и `PROJECT_SPEC.md` необязательны.
2. Если уже опубликована V3, замените четыре файла `index.html`, `style.css`, `app.js`, `data.js` на одноимённые файлы V4. Перейдите на опубликованный сайт и обновите страницу (при необходимости Ctrl+F5).
3. В GitHub открыть **Settings → Pages → Build and deployment** → **Deploy from a branch** → `main` → `/(root)` → **Save**. Дождаться опубликования.
4. Открыть адрес `https://<имя-пользователя>.github.io/<имя-репозитория>/`.
5. Возможно также открыть `index.html` на компьютере (некоторые настройки браузера могут ограничивать локальное хранение, лучше тестировать на GitHub Pages).

## Что исправлено в V4: олимпиады создаются как обычные допы

**Теперь олимпиада — направление с типом `olympiad`, собственной группой и расписанием.**

1. Методолог выбирает свой филиал и параллель → **«Допы и расписание»**.
2. В поле **«Тип допа»** выбирает «Олимпиада». Вводит название, например «Олимпиада по математике», группу и слоты расписания. Нажимает «Создать доп и группу».
3. Открывает **«Олимпиады»** и выбирает созданную группу из списка. Галочками отмечает учеников, которым доступно предложение, и нажимает «Назначить предложения».
4. У выбранного ученика появляется конкретная олимпиада с её группой и временем, которую можно принять или не принимать. При принятии система проверяет пересечения.
5. Название и расписание олимпиады хранятся в группе, а не копируются в каждого ученика. Одну группу можно предложить нескольким ученикам. Уже предложенные группы нельзя удалить или поменять их расписание, пока предложения существуют.

Олимпиады не выводятся в открытом общем списке допов ученика, пока методолог их не предложит; ученику не предлагаются группы другого филиала или параллели. В демонстрации поддерживается одно текущее предложение олимпиады на ученика, при необходимости его можно заменить до принятия и подтверждения. Другие допы по-прежнему выбираются вручную без ограничения количества, с проверкой временных конфликтов.

Демо-олимпиады из Excel преобразованы в настоящие группы с тестовыми названиями и расписаниями, их прежние предложения сохранены. **При открытии V4 на том же адресе GitHub Pages** приложение пытается прочитать локальные записи V3 и перенести предложения на группы. Не удаляйте данные браузера перед обновлением, если хотите их сохранить. Для переноса на другой компьютер по-прежнему нужна общая серверная база.

Другие разделы V3 сохранены: создание учеников, отчёты, обычные группы и расписание, подтверждение и повторное открытие выбора методологом, экспорт JSON.

## Проверка на тестовых данных

1. **Методолог** → филиал №1 → 2-я параллель → «Ученики»: создайте «Тестовый Новый».
2. **«Допы и расписание»** → тип «Олимпиада» → название «Олимпиада по математике» → группа «А» → ВТ, доп №2 → «Создать доп и группу».
3. **«Олимпиады»** → в выпадающем списке выберите «Олимпиада по математике · группа А» → найдите «Тестовый Новый» → отметьте галочкой → «Назначить предложения».
4. В «Ученики» откройте созданного ученика: предложение доступно, но **ещё не принято**. Включите его и подтвердите расписание.
5. Вернитесь к методологу: группа олимпиады защищена от редактирования, в назначениях отображается статус «Принято и подтверждено».
6. У ученика другого филиала/параллели это предложение не появится. Противоречащие по времени обычные группы будут недоступны.

## Данные, безопасность и ограничения

- Изменения пишутся **только в `localStorage` браузера**, **не в репозиторий GitHub**. Другие устройства, браузеры и пользователи их не увидят. При очистке данных браузера изменения исчезнут.
- В админке есть **экспорт текущих изменений в JSON** для просмотра или дальнейшего переноса; обратный импорт в V4 пока не предусмотрен. Не считайте этот экспорт полноценным резервным восстановлением.
- При первом запуске V3 приложение пытается прочитать локальные подтверждения из V2 в том же браузере и на том же сайте. V4 использует отдельный ключ хранения и читает V3/V2 как источник при первом запуске на том же домене.
- Кнопка «Сбросить все изменения» восстанавливает исходные учебные данные V4 и сбрасывает выборы только в данном браузере.
- **В реальной системе каждый методолог закреплён за одним филиалом**. Переключатель филиалов в демонстрации лишь имитирует разные кабинеты. Настоящих пользователей, паролей, ролей и прав нет.
- Для совместного использования несколькими методологами и учениками нужна серверная БД, аутентификация и серверная проверка полномочий. Для настоящих ФИО и данных школьников текущая публичная версия **не предназначена**.
- Расписание использует два фиксированных слота из Excel (15:20–16:20 и 16:30–17:30, понедельник–пятница). Гибкое время, ограничение мест, импорт списка учеников и уведомления можно добавить на следующих этапах.
- В Excel не было распределения групп по филиалам: скопированные для второй параллели группы и группы параллелей 1, 3 и 4 — **только тестовые данные**.
