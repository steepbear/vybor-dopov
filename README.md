# Выбор допов — GitHub Pages, прототип V2

Демонстрация ручного выбора дополнительных занятий для **нескольких филиалов** и **1–4 параллелей**. Одинаковое название направления может использоваться в разных филиалах и параллелях, но группы и расписания самостоятельные.

## Публикация

1. Создайте отдельный репозиторий на GitHub, например `vybor-dopov`.
2. В корне репозитория разместите файлы `index.html`, `style.css`, `data.js`, `app.js` (именно из V2). По желанию `README.md` и `PROJECT_SPEC.md`.
3. В репозитории: **Settings → Pages → Build and deployment → Deploy from a branch → main → /(root)**.
4. После публикации откройте ссылку GitHub Pages. Можно также запускать `index.html` локально.

## Что проверить

1. В режиме ученика смените **филиал** и **параллель** (1–4). Список групп сменится. Одно название допа встречается в нескольких параллелях с независимыми расписаниями.
2. Выберите группу «Карате» в 1-й параллели филиала №1. Группа «Студия юнного художника» станет недоступной из-за общего временного слота.
3. Смените филиал на №2: ранее выбранное занятие не переносится другому ученику, а идентификаторы групп других филиалов не доступны.
4. Во 2-й параллели попробуйте ручной выбор, олимпиаду и необязательный помощник по приоритетам, затем подтвердите.
5. В панели методолога выберите филиал и параллель: сводки и подтверждения относятся только к ним. Методолог может открыть подтверждённый выбор обратно в демо-режим редактирования.

## Важное про тестовые данные

Excel даёт 54 вымышленных ученика второй параллели, 16 направлений и 28 групп, **но не указывает филиал каждой группы**. Поэтому в V2 шаблоны расписаний второй параллели продублированы отдельно для трёх филиалов исключительно для тестирования. Для 1-й, 3-й и 4-й параллелей также добавлены **вымышленные** ученики и группы. Реальное расписание каждого филиала потребуется импортировать отдельно.

Прототип не управляет настоящими персональными данными. Пароли из Excel не импортируются. Данные сохраняются в `localStorage` браузера; общей базы и защищённой авторизации нет. В режиме методолога можно свободно переключать любой филиал — **только в демонстрации**.

Реальные ограничения филиалов и параллелей должны проверяться на сервере после внедрения аутентификации. Изменение предложений и расписаний из веб-интерфейса ещё не реализовано. Технические детали и открытые вопросы — в `PROJECT_SPEC.md`.
