# Выбор допов — архитектура V9 (утверждено 12.11.2026)

> V9 разрабатывается в основной ветке `main`; V8 — только источник существующего кода и механик. Это описание целевого состояния, не описание уже применённой схемы Supabase.

## 1. Справочники

- **Ученик**: постоянный UUID/GUID, филиал, привязанная учётная запись, неизменный логин. Фамилия и имя **не хранятся в Supabase**. ФИО присутствуют только в локальном школьном реестре `.vdop`.
- **Доп (направление)**: постоянный UUID/GUID, название. Создаётся один раз, не закрепляется за параллелью.
- **Филиал**: постоянный UUID/GUID и название.
- **Учебный год**: значение года начала, например `2026` означает `2026/2027`. Отдельный справочник лет не обязателен.

## 2. Документ «Класс»

Уникальность документа: **(учебный год, филиал, параллель 1–4, буква класса)**. Например 2026/2027 — Крымская — 2 — А.

Состав (табличная часть): GUID учеников. Один ученик может состоять не более чем в одном классе данного филиала **в рамках одного учебного года**. Идентичность ученика от класса не зависит.

Статусы: **Формируется → Активен → Завершён**. Завершённые документы и история сохраняются; изменения состава после завершения по умолчанию запрещены.

## 3. Документ «Расписание допов»

Уникальность: **(учебный год, филиал)**. Статусы аналогичные.

Табличная часть включает **группы** с указанием постоянного GUID допа, типа (обычный доп / олимпиада), имени группы и временных слотов.

- У одного допа может быть несколько групп одного филиала.
- Параллель — необязательное ограничение **группы**, а не допа: пустой набор означает 1–4, указанное множество — только выбранные параллели (например 1 и 2).
- При проверке пересечений учитывать выбранные группы обычных допов и принятых олимпиад.

## 4. Выбор ученика

Связывает постоянный GUID ученика и группу из документа расписания **того же учебного года и филиала**. Перед записью проверяются зачисление в документ класса, доступность группы по параллели, пересечения, срок выбора, подтверждение, статус документов.

Подтверждение выбора, включая пустой выбор по отдельно установленным правилам, должно храниться **в разрезе учебного года**, не в постоянной карточке ученика.

## 5. Массовый перевод

Раздел методолога: **«Учебный год»**.

1. Выбрать исходный и целевой годы для своего филиала.
2. Сформировать соответствия документов класса (1А → 2А, 2А → 3А, 4А → Выпуск); просмотреть составы.
3. Допустить индивидуальные исключения: другой класс, повтор года, выбытие.
4. Предварительная проверка: уникальность целевых документов и отсутствие повторного зачисления в целевом году.
5. После подтверждения — записать зачисления в документы целевого года; прежняя история неизменна. Завершать исходные документы **явным отдельным действием**, чтобы не блокировать проверку частичного перевода.
6. Постоянный GUID, логин, пароль ученика не изменять; назначения допов следующего года не копировать.

Повторное проведение перевода — идемпотентное (не создаёт повторных зачислений).

## 6. Формат .vdop

Версионированный **локальный формат** «Выбора допов», расширение `.vdop`; не является шифрованием.

Реестр создаётся из одного XLSX по параллели или открывается из существующего `.vdop`. Редактор предоставляет добавление, удаление строк, исправление ФИО и букв классов, проверку дублей, сохранение. **GUID выдается локально один раз**, сохраняется при редактировании имени/класса и проверяется по UUID в Supabase при импорте. ФИО никогда не передавать на сервер.

В файле v1: `format, version, kind, registry_id, branch_id, branch_name, year_start, grade, students[]`, в каждой строке `id, surname, name, class_letter, login` (логин может быть пустым до выдачи учётной записи). Пароли в постоянном `.vdop` **не хранить**; созданные пароли выгружаются отдельным одноразовым Excel.

Совпадение (буква класса + фамилия + имя) — конфликт только в локальном редакторе. Реальная повторная загрузка проверяется по GUID. Файл другого филиала отклоняется.

### Механизм ручного редактирования и загрузки

- **Новый пустой реестр** создаёт пустой документ **в браузере**, но не сохраняет файл на диске.
- **Создать из Excel** — режим **полной замены**. Если реестр уже открыт, сначала спрашиваем ровно: «Текущие данные будут заменены данными из файла. Продолжить?». Ответ «Нет» отменяет операцию. После «Да» выбираем XLSX одной параллели, проверяем файл и только при успешном чтении полностью заменяем список, выдавая новые GUID. Данные не дописываются к прежним строкам.
- Ошибочный XLSX или отмена выбора файла **не очищают** уже открытый реестр.
- **Открыть .vdop** загружает локальный ранее сохранённый реестр в редактор; при несохранённых изменениях действуют предупреждения о замене. **Закрыть реестр** выгружает его из редактора, не удаляя файл с устройства.
- **Ручное редактирование** ФИО и буквы класса, добавление и удаление учеников разрешены. Параллель показана отдельным нередактируемым полем, потому что задаётся на весь реестр. GUID существующего ученика при изменении ФИО или класса не меняется.
- **Сохранить .vdop** — отдельная команда, скачивающая полный новый файл. Все данные до сохранения находятся в памяти браузера; автозаписи в локальный файл или Supabase нет.


## 7. Логины

Формат `2026_2А_Ученик_01` утвержден. Год и класс — дата первоначального выпуска, **не актуальный класс**. Логин неизменен. Уникальность обеспечивается сервером во всей системе; при конфликте увеличивается номер. Пароли создаются сервером и не сохраняются открытым текстом в БД/в постоянном локальном реестре.

## 8. Порядок реализации

1. Локальный редактор `.vdop` на основном сайте (код в `main`) без изменений схемы Supabase.
2. Новая модель документов классов, расписания, составов, выбора, RLS и серверной проверки.
3. Безопасное создание учётных записей из `.vdop`, новый формат логина, отчёт с выданными паролями.
4. Перенос существующих интерфейсов методолога/ученика, включая олимпиады, отчёты и дедлайны.
5. Раздел «Учебный год» и массовый перевод.
6. Полное сквозное тестирование на тестовых данных, затем переход V9.

**Важно:** разработка V9 идёт на основном GitHub Pages; текущая схема Supabase сохраняется до выполнения этапов миграции.
